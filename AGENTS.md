# Project implementation rules

- Keep the centred operational popup entrance animation in the global theme so Orders, Collections, Deliveries, and other order surfaces share identical motion.
- Position custom right-click menus with the shared viewport-aware hook so they flip and remain fully visible near every screen edge.- Comment push: notifications INSERT trigger -> send-push edge fn (VAPID web push, claims row via pushed_at); SW push handlers live in public/push-sw.js imported by workbox; native app uses local notifications while open. Why: one pipeline for every device.
- Windows app: desktop/ Electron shell loading the live site, built to an NSIS .exe on windows-latest in the same workflow and attached to the same GitHub release as the APK. Why: real installer that always stays up to date, and releases/latest serves both files.
- Fabrication projects: fabrication_* tables + private fabrication-files bucket (signed URLs); A4 PDF built client-side in src/lib/fabricationPdf.ts. Why: one self-contained workspace that prints without a server.
- Buying Sheet: procurement helpers calculate demand net of received and Zoho-invoiced units, and pool open-PO units (from zoho_document_cache via get_buying_sheet_live_coverage) once per SKU oldest-first; all views share row-key selection, and reads use bounded pagination. Why: prevent duplicate purchasing without Zoho API calls.
- Buying Sheet uses app-level fullscreen below portalled dialogs and menus; copy actions use awaited clipboard fallback and explicit error feedback. Why: keep notes, emails and actions usable in browser and app views.
- Native lifecycle, Android Back and comment notification listeners mount at the app shell; device opt-out overrides OS permission, and missing native plugins require an APK update. Why: behavior must remain consistent across workspaces and Settings without claiming foreground alerts are remote push.
- Commission profit-split rules and cost-basis caps live in src/lib/commissionRules.ts and are mirrored in the rep-commission-data edge function; test both calculations together and bump report_version when rules change. Why: client overrides and server reports must agree and stale caches must recalc.
- Commission vendor costs use exact text then stable item identity in costMatching.ts; shared generic products cannot use SKU/ID fallback, and incomplete bill reads must not overwrite reports. Why: prevent missing or unrelated costs from changing payouts.
- Commission vendor bills are read once into commission_bill_cache (keyed by bill_id + last_modified_time) with retried, time-budgeted Zoho reads; an unfinished read keeps progress and the page auto-continues. Why: Zoho drops long bill scans, which left stale description-only reports.
